## データモデル

| テーブル | 意味 |
| --- | --- |
| `questions` | 固定ID、問題文、正解・別解、読み上げ用文章、分野、出典、解説、出題用の乱数キー |
| `question_sets` | 問題集名と作成日時。空文字は既存問題の未分類 |
| `favorites` | 問題IDにひも付くお気に入り |
| `rounds` | 一巡の番号と乱数順の開始位置 |
| `attempts` | 出題・回答の履歴。出題時の問題・正解・別解・読み上げ文・解説なども保存 |
| `settings` | 1行だけの設定。読み上げ速度と問題文表示 |

現在、テーブルにユーザーIDを持たず、所有者1名のデータを共有する。単にログイン許可メールを増やしてもユーザーごとのデータ分離にはならない。複数ユーザー化は認証・スキーマ・クエリ・既存データの移行を伴う設計変更になる。

問題集単位の削除は管理画面・APIに対応。問題単体の削除画面はない。履歴の参照整合性を維持するため、問題は論理削除する。

## 出題・回答で維持すること

1. 出題順は `questions.random_key` の索引順と `rounds.start_key` で選び、範囲の末尾から先頭へ回る。一巡ごとの完全に独立したシャッフルではない。
2. `UNIQUE(round_id, question_id)` で同じ一巡の重複を防ぐ。`attempts_one_pending` の部分一意索引で、一巡内の未回答を1件に保つ。
3. 問題の取得時点で `attempts` に出題を保存する。読み上げ開始前に閉じても、その問題から再開する。進み具合の表示は未回答の1問を除く。
4. 未回答があるときの「次の問題」は同じ出題を返す。一巡終了後は明示した操作で次の一巡を始める。
5. 回答は `answered_at IS NULL` の場合だけ更新する。再送で回答履歴を重複させたり、最初の判定を書き換えたりしない。
6. 出題後の問題編集・CSV更新は現在の出題や過去の判定を書き換えない。判定には `attempts` のスナップショットを使う。
7. 未回答の練習APIは正解・別解・解説を返さない。問題本文は含まれ、読み上げ中の非表示は画面の挙動として実装している。
8. スキップは履歴に残すが、正解率と解答数の集計から除く。手動で正解扱いにした履歴には `overridden` を残す。
9. 履歴日時の保存と、日本時間での日別集計・表示を区別する。

クエリや状態遷移を変更するときは、統合テストの同時操作・一巡・再開・更新後のスナップショット・再送の確認を維持する。画面だけのガードで重複を防ごうとしない。

## 問題登録・判定

- CSVはブラウザで解析してプレビューするが、APIでもZodによる検証を行う。
- CSVは1ファイル10,000問・4MBまで。画面から200問ずつ登録し、APIの1要求の上限は500問。途中失敗時は登録済み件数を案内し、同一IDで再取り込みする。
- CSVはUTF-8、別解・再回答候補の区切りは `|`。DBではそれぞれJSON文字列として保存する。
- 固定IDを使ったupsertで問題を更新する。ID・登録日時・乱数キーと、お気に入りの対応を維持する。
- 手入力の新規登録で既存IDを指定した場合は409。CSVの同一ID更新はプレビューで件数を示し、画面で確認してから取り込む。
- 正解照合はNFKC → trim → 小文字化 → 正解・別解との完全一致。ひらがな・カタカナ、略称、内部空白、句読点は別解なしに同一視しない。
- 問題収集元は未決定。初版の登録経路は手入力・CSV。外部収集サービスは組み込んでいない。

問題・履歴の一覧は20件ずつ取得する。出題のたびに全件ランダムソートを追加しない。大量データへの拡張時には、D1の読み取り行数と索引、全件書き出し時のメモリ使用も確認する。JSON書き出しは全データをまとめて扱うため、大きなバックアップにはD1のSQL exportを使う。

### 問題集・ジャンル・再回答

`0002_collections_and_retry.sql` は列とテーブルを追加する互換マイグレーション。`questions.collection`、`majorCategory`、`minorCategory`、`retryAliases` を追加し、既存問題は空の問題集・ジャンル、再回答候補なしとする。問題保存と問題集の作成は同じD1 batchで実行する。問題集名で管理一覧を絞り込み、`questions_collection` 索引を持つ。

`attempts` にも4項目のスナップショットを保存。`retry_requested` は再回答待ちの表示状態で、△一致時は `answered_at IS NULL` のまま保持し、判定済みの履歴を作らない。確定回答・スキップで解除する。正解・別解と△が重なる場合は正解を優先する。未回答APIは△候補自体を返さない。

番号付きの日本語CSVは問題集名をエスケープした接頭辞と元番号でIDを作る。○・△・×の解析は共有コードに置き、×の行はメモにも残さない。問題本体はGitに含めず、取り込み用の個人データは `.wrangler/` など除外済みの保存先で扱う。通常CSVの書き出しには新しい列を含め、再取り込みで保持する。JSON書き出しはversion 3となり、空の問題集と削除済み問題も含む。

### 問題集の変更・削除

共有スキーマはshared/collections.ts。PUT /api/collections は問題集名と所属問題のcollectionを同じD1 batchで更新する。固定IDとattemptsのスナップショットは変更しない。GET /api/collections/export?name=... はその問題集の有効な問題を返す。

0003_collection_management.sql はquestions.deleted_atとattempts.cancelled、および有効な問題用の索引を追加する。DELETE /api/collections は名前の一致と表示時の問題数を検証し、お気に入り解除・未回答出題の中止・問題の論理削除・問題集行の削除を同じbatchで実行する。各更新はトランザクション内でも件数を確認し、並行した追加で削除対象が増えた場合は処理しない。中止した出題はanswered_atを埋めて未回答一意制約を解放するが、履歴・成績・一巡の進捗から除外する。

問題一覧・出題・問題数・進捗・お気に入り・音声生成は削除済みの問題を対象外とする。次の出題のINSERTも有効な問題の存在を再確認し、同時削除時の新たな未回答作成を防ぐ。通常CSV用のquestionsは有効な問題だけで、全データJSONのdeletedQuestionsには削除済み問題を保持する。再取り込みのupsertはdeleted_atを解除する。回答済み履歴と一巡内のID重複制約は引き続き維持する。

## 読み上げとiPhone

### Google音声の追加（2026-11-07）

`TTS_PROVIDER=google` でGoogle音声を選択。Standard（A〜F）とChirp 3 HDに対応。ローカル・本番ともGoogle音声の設定で、本番は公開前にWorkerのシークレット登録が必要。`GOOGLE_TTS_API_KEY` はWorkerの秘密設定、`GOOGLE_TTS_VOICE` は日本語の音声名（既定 `ja-JP-Standard-D`）。認証済みの `GET /api/speech/config` は音声名と設定済みフラグだけを返す。`POST /api/speech` は `shared/speech.ts` の出題IDを検証し、D1の出題スナップショットから読み上げ文を取得する。任意の文章を直接送るAPIにはしない。

`worker/speech.ts` からGoogle REST APIを呼び出し、MP3を返す。キーはヘッダーにだけ入れ、Googleの生のエラーは記録・返送しない。30秒のタイムアウト、UTF-8で5,000バイトの上限を設ける。音声も既存のAccess認証とOrigin検証を通し、`no-store`。CSPは同一オリジンとblob音声だけを許可。

画面は出題ID・未回答状態・音声設定を監視し、未回答の問題の音声を自動取得する。準備完了後にHTMLAudioElementを自動再生する。「次の問題へ」のタップ時に短い無音WAVで同じ音声要素を再生し、非同期の問題・音声取得後も要素を再利用する。自動再生が拒否された場合は明示的な再生ボタンを表示。準備中は状態だけを表示し、失敗時はボタンから再試行する。再開した再回答待ちの出題は自動再生しない。再生速度は端末のplaybackRateで変更する。同じ出題の読み直しはメモリ内の音声を使う。停止・画面移動は再生を止め、準備中の応答も世代番号で無効化。画面移動・問題更新でblob URLを解放する。永続キャッシュ・本番用Googleキーの登録は別途。

### 固定の告知と読み上げ文の加工

`public/audio/question.mp3` はStandard-Dで一度生成した「問題」。ビルド時にdistへコピーされ、既存の認証を通して配信される。`npm run speech:intro` はローカルの環境変数／`.dev.vars` を通常の設定として読み、固定文だけをGoogleへ送ってこの音声を再生成する。APIキーを音声・ログ・ソースへ保存しない。

`src/speech.ts` は同じ音声要素で告知を通常速度で再生し、endedから300ms後に本文を開始。停止・移動は告知イベントとタイマーを解除する。告知が失敗した場合は本文を開始せず、再生の再試行を案内する。Google音声・ブラウザ音声の両方で使い、本文の速度設定とは独立させる。

`shared/speech.ts` の `spokenText` が全角・半角の丸括弧と中身を入れ子も含めて除去。Google音声はWorkerの `synthesize` 内で加工し、ブラウザ音声も同じ関数を使う。加工はバイト上限チェックより前に行い、空文字は拒否する。出題スナップショット・問題・表示用文章は変更しない。

### ブラウザ音声

- ブラウザの `speechSynthesis` を使う場合も出題に合わせて自動再生を試み、失敗時はタップで再試行できる。
- 読み上げの世代を管理し、準備完了や再描画で同じ出題を繰り返し自動再生しない。
- 停止、画面移動、読み直し時に前の音声をキャンセルする。古い音声のイベントで新しい問題の画面状態を更新しないよう、世代を管理している。
- 読み上げ開始に失敗した場合の案内と「文字を見て回答」を残す。
- 初版の音声回答はOSのキーボードの音声入力。アプリによる録音・音声認識は追加仕様。
- 画面幅の確認やPCの音声動作だけで、iOSの音声エンジンの動作確認済みとは扱わない。

## 認証・公開設定

`OWNER_EMAIL`、`ACCESS_TEAM_DOMAIN`、`ACCESS_AUD`を使い、Accessの公開鍵でJWTを検証する。メールのヘッダーだけを信頼したり、トークンを単にdecodeする実装に変更しない。更新APIのOrigin・JSON形式のチェックも維持する。

`wrangler.jsonc`は本番、`wrangler.local.jsonc`はローカル専用。同じD1 IDを記述していても `--local` はローカルのエミュレーターに保存する。ローカル設定の存在を根拠に `--remote` を付けない。

本番URLを変更するときは以下を一緒に確認する:

- Accessの対象ホストと許可ルール、Workerのissuer・audience
- `wrangler.jsonc`のroutes・workers_dev・preview_urls
- `.github/workflows/ci-cd.yml`のEnvironment URL・実行結果のURL
- `scripts/check-production.mjs`の接続先（現在はURLを直接記述）
- READMEと仕様・運用資料

`check-production.mjs`は現在 `wrangler.jsonc` を `JSON.parse` している。設定にJSONCのコメント・末尾カンマなどを導入する場合は、読み取り側も合わせて変更する。
